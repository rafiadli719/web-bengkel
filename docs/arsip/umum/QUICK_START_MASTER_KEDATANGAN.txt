📋 INSTALASI CEPAT
═══════════════════════════════════════════════════════════════

1. IMPORT DATABASE
   ─────────────────────────────────────────────────────────────
   • Buka phpMyAdmin atau MySQL Command Line
   • Pilih database: fitmotor_dbbengkel
   • Import file: database_master_kedatangan_pelanggan.sql
   
   Via Command Line:
   mysql -u root -p fitmotor_dbbengkel < database_master_kedatangan_pelanggan.sql

2. REFRESH DATA AWAL (Opsional)
   ─────────────────────────────────────────────────────────────
   Jika sudah ada data servis lama, jalankan:
   
   CALL sp_refresh_master_kedatangan();
   
   • Ini akan generate data kedatangan dari semua transaksi lama
   • Proses bisa memakan waktu 1-5 menit tergantung jumlah data

3. VERIFIKASI INSTALASI
   ─────────────────────────────────────────────────────────────
   • Cek total record:
   SELECT COUNT(*) FROM master_kedatangan_pelanggan;
   
   • Lihat data sample:
   SELECT * FROM view_ringkasan_kedatangan_pelanggan LIMIT 10;

📊 KONSEP DASAR
═══════════════════════════════════════════════════════════════

PERBEDAAN SISTEM LAMA VS BARU
─────────────────────────────────────────────────────────────

Sistem Lama (Statistik):
• Basis: Total nominal transaksi (Rupiah)
• Member: Bronze < 2jt, Silver 2-5jt, Gold 5-10jt, Platinum >10jt
• Focus: Nilai transaksi

Sistem Baru (Kedatangan):
• Basis: Jumlah kunjungan (Frekuensi)
• Member: Bronze <5x, Silver 5-10x, Gold 10-20x, Platinum >20x
• Focus: Loyalitas pelanggan

KATEGORI MEMBER BARU
─────────────────────────────────────────────────────────────

🥉 Bronze    : < 5 kunjungan
🥈 Silver    : 5-9 kunjungan (Diskon 10%)
🥇 Gold      : 10-19 kunjungan (Diskon 15%)
💎 Platinum  : ≥ 20 kunjungan (Diskon 20%)

⚙️ CARA KERJA TRIGGER
═══════════════════════════════════════════════════════════════

ALUR OTOMATIS
─────────────────────────────────────────────────────────────

1. Kasir input servis seperti biasa
2. Kasir klik tombol BAYAR
3. Status servis berubah: 'selesai' → 'bayar'
4. Trigger otomatis jalan di background
5. Sistem catat kedatangan ke tabel master_kedatangan_pelanggan
6. Data tersimpan otomatis (kasir tidak perlu lakukan apapun!)

DATA YANG DICATAT
─────────────────────────────────────────────────────────────

• Kedatangan ke berapa (1, 2, 3, dst)
• Tanggal datang sekarang
• Tanggal datang sebelumnya
• Jarak hari dari kunjungan sebelumnya
• Total transaksi
• Jumlah item servis
• Rata-rata nilai per item
• Estimasi datang berikutnya (+30 hari)
• Status garansi

📊 QUERY PENTING
═══════════════════════════════════════════════════════════════

1. LIHAT RINGKASAN SEMUA PELANGGAN
   ─────────────────────────────────────────────────────────────
   SELECT * FROM view_ringkasan_kedatangan_pelanggan
   ORDER BY jumlah_kedatangan DESC
   LIMIT 50;

2. LIHAT RIWAYAT KEDATANGAN PER PELANGGAN
   ─────────────────────────────────────────────────────────────
   SELECT * FROM view_riwayat_kedatangan_detail
   WHERE no_pelanggan = 'AD 1234 AB'
   ORDER BY kedatangan_ke DESC;

3. PELANGGAN PERLU FOLLOW-UP
   ─────────────────────────────────────────────────────────────
   SELECT * FROM view_pelanggan_perlu_followup
   WHERE prioritas = 'Urgent'
   ORDER BY hari_tidak_datang DESC;

4. TOP 10 PELANGGAN SETIA
   ─────────────────────────────────────────────────────────────
   SELECT * FROM view_top_pelanggan_kunjungan
   LIMIT 10;

5. ANALISIS POLA KUNJUNGAN
   ─────────────────────────────────────────────────────────────
   SELECT 
       kedatangan_ke,
       COUNT(*) AS jumlah_pelanggan,
       AVG(jarak_hari) AS rata2_jarak_hari,
       AVG(total_transaksi) AS rata2_transaksi
   FROM master_kedatangan_pelanggan
   WHERE kedatangan_ke > 1
   GROUP BY kedatangan_ke
   ORDER BY kedatangan_ke;

🔧 TROUBLESHOOTING
═══════════════════════════════════════════════════════════════

PROBLEM: Trigger tidak jalan
─────────────────────────────────────────────────────────────
SOLUSI:
• Cek trigger exist: SHOW TRIGGERS LIKE 'tblservice';
• Cek status servis berubah ke 'bayar'
• Cek foreign key constraint (no_pelanggan harus exist)

PROBLEM: Data tidak muncul di view
─────────────────────────────────────────────────────────────
SOLUSI:
• Cek view exist: SHOW FULL TABLES WHERE Table_type = 'VIEW';
• Refresh view: DROP VIEW dan CREATE VIEW ulang
• Cek data di tabel master: SELECT * FROM master_kedatangan_pelanggan;

PROBLEM: Performa lambat
─────────────────────────────────────────────────────────────
SOLUSI:
• Cek index: SHOW INDEX FROM master_kedatangan_pelanggan;
• Tambah index jika perlu
• Optimize table: OPTIMIZE TABLE master_kedatangan_pelanggan;
