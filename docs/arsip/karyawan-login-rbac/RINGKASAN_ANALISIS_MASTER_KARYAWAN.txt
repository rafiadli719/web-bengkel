- tb_user_account (11 records - NEW)
  * Kolom utama: username, password_hash, user_akses_level, kode_karyawan

  * FK ke: tb_master_karyawan, tb_user_roles

- tbuser (12 records - LEGACY)
  * DEPRECATED! Masih ada tapi tidak digunakan
  * Password dalam PLAIN TEXT (BERBAHAYA!)

- tb_user_roles (3+ records)
  * Kolom utama: role_code, role_name, permissions (JSON)
  * Permissions: ["all"], ["service_read", "service_create", ...]

- tb_user_mekanik_mapping
  * Relasi many-to-many antara user dan mekanik
  * Untuk kepala mekanik yang supervise multiple mekanik

⚠️ CRITICAL ISSUES
================================================================================

1. DUAL USER SYSTEM (SECURITY RISK)
   Problem: Ada 2 sistem user berjalan bersamaan
   - tbuser (LEGACY) - Password PLAIN TEXT
   - tb_user_account (NEW) - Password masih PLAIN TEXT
   Impact: Confusing, maintenance nightmare, security risk
   Solution: Migrate semua ke tb_user_account, hapus tbuser

2. PASSWORD SECURITY (🔴 CRITICAL)
   Problem: Password disimpan dalam PLAIN TEXT
   Risk: Jika database bocor, semua password terbaca
   Solution: Gunakan password_hash() PHP untuk hashing

3. SQL INJECTION VULNERABILITIES
   Problem: File master-posisi.php masih vulnerable
   Example: "SELECT * FROM tb_master_posisi WHERE id = '$edit_id'"
   Solution: Gunakan prepared statements

4. MISSING FOREIGN KEY CONSTRAINTS
   Problem: Relasi antar tabel tidak ada FK constraint
   Impact: Data integrity tidak terjamin, orphan records bisa terjadi
   Solution: Tambah FK constraints di database

5. MISSING DATABASE INDEXES
   Problem: Tidak ada index di foreign keys
   Impact: Query lambat untuk join
   Solution: Tambah indexes untuk kode_posisi, kode_level, kode_karyawan, dll


🟡 MEDIUM ISSUES
================================================================================

6. INCONSISTENT NAMING CONVENTION
   - kode_karyawan vs nomekanik
   - kode_posisi vs nama_posisi
   Solution: Standardize naming convention

7. NO AUDIT TRAIL
   - tb_user_activity_log ada tapi tidak digunakan konsisten
   Solution: Implement logging di semua CRUD operations

8. NO INPUT VALIDATION
   - File master-posisi.php hanya sanitasi, tidak ada validation
   Solution: Tambah validation untuk format, range, dll

9. INCONSISTENT SOFT DELETE
   - tbuser uses status_row dan is_active
   - tb_master_karyawan tidak ada soft delete column
   Solution: Standardize soft delete dengan is_active enum


✅ GOOD PRACTICES FOUND
================================================================================

1. Timestamps: created_at dan updated_at di semua table
2. Enum Types: Menggunakan ENUM untuk status yang terbatas
3. Separation of Concerns: User account terpisah dari data karyawan
4. Master Data Structure: Posisi dan Level terpisah (normalisasi baik)
5. Role-Based Access: tb_user_roles dengan JSON permissions
